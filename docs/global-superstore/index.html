Modeling decision log

Các quyết định có thể bảo vệ trong design review

Vấn đề nguồnQuyết định triển khaiLý do và trade-off
Order ID không duy nhất toàn cục

Tạo order_key deterministic từ toàn bộ natural grain của order header.

Join ổn định và tái tạo được; business ID vẫn được giữ làm attribute.

Product ID thay đổi mô tả

Tạo product_key từ Product ID cùng category, sub-category và product name.

Không ép một mô tả tùy ý thành “đúng”; đổi lại một Product ID có thể ánh xạ nhiều analytical member.

Geography không có natural key ổn định

Hash đầy đủ market, region, country, state, city và postal code.

Loại join bằng free text trong fact; cần governance nếu geography thay đổi theo thời gian.

Encoding và date format không mặc định

Đọc CSV bằng Windows-1252 và parse date với format %d-%m-%Y, lỗi thì dừng build.

Transformation tường minh và audit được; tránh phụ thuộc locale của môi trường chạy.

Date có hai vai trò

Dùng một dim_date, join bằng order_date_key hoặc ship_date_key theo ngữ cảnh.

Tránh duplicate date dimension nhưng query phải đặt alias rõ ràng.

Fact cần scan theo năm

Hive partition cả hai fact bằng order_year; field nằm ở directory.

Partition pruning tốt hơn, không lặp giá trị năm trong mỗi row Parquet.

Analytical SQL

Query phải đúng grain, có denominator và tự kiểm chứng

DuckDB đọc Parquet trực tiếp. Mỗi analysis query đi qua bốn lớp: register views, validate contract, compute metric và reconcile output.

Query protocol

Quy trình phân tích tái lập

  1. 01Register

    Tạo logical view, bật Hive partitioning và đặt alias có ngữ nghĩa.

  2. 02Validate

    Kiểm row count, uniqueness, orphan key và phạm vi date trước khi aggregate.

  3. 03Compute

    Khai báo numerator, denominator, filter context và grain của kết quả.

  4. 04Reconcile

    Đối chiếu subtotal với control total; document mọi exclusion.

Register views

Đọc fact từ Hive partitions

hive_partitioning = true khôi phục order_year từ directory. Filter theo năm có thể loại partition trước khi scan row groups.

Output grainView giữ nguyên source fact grain.Control51.290 line items, 2011-2014.
01_register_views.sql
CREATE OR REPLACE VIEW fact_order_line AS
SELECT *
FROM read_parquet(
  'data/global_superstore/facts/fact_order_line/**/*.parquet',
  hive_partitioning = true
);

SELECT
  order_year,
  COUNT(*) AS line_items,
  ROUND(SUM(sales), 2) AS control_sales,
  ROUND(SUM(profit), 2) AS control_profit
FROM fact_order_line
GROUP BY order_year
ORDER BY order_year;
Quality assertion

Chứng minh join không làm mất dòng

Anti-join đo orphan key. Kết quả mong đợi là 0; nếu lớn hơn 0, dừng analysis và xử lý model.

Test typeReferential integrityExpectedorphan_products = 0
02_quality_assertion.sql
SELECT COUNT(*) AS orphan_products
FROM fact_order_line AS line
LEFT JOIN dim_product AS product
  USING (product_key)
WHERE product.product_key IS NULL;

SELECT
  COUNT(*) AS line_items,
  COUNT(DISTINCT line_item_key) AS unique_lines,
  COUNT(DISTINCT order_key) AS orders
FROM fact_order_line;
Executive KPI

Growth và profitability theo category

Fact line cung cấp measure tài chính; fact order cung cấp order date; dim product cung cấp analytical hierarchy.

Denominator ruleProfit margin = SUM(profit) / SUM(sales). Không lấy trung bình margin từng dòng.
03_category_performance.sql
SELECT
  date.year_month,
  product.category,
  COUNT(DISTINCT ord.order_key) AS orders,
  ROUND(SUM(line.sales), 2) AS sales,
  ROUND(SUM(line.profit), 2) AS profit,
  ROUND(
    SUM(line.profit)
    / NULLIF(SUM(line.sales), 0) * 100,
    2
  ) AS profit_margin_pct
FROM fact_order_line AS line
JOIN fact_order AS ord USING (order_key)
JOIN dim_date AS date
  ON date.date_key = ord.order_date_key
JOIN dim_product AS product USING (product_key)
WHERE ord.order_year = 2014
GROUP BY date.year_month, product.category
ORDER BY date.year_month, sales DESC;
Diagnostic query

Định lượng discount risk theo band

Bucket giúp quan sát mối liên hệ phi tuyến giữa discount và margin. Đây là association, chưa phải causal effect.

Output grain1 row / discount bandDecisionXác định band cần drill-down theo product và market.
04_discount_risk.sql
WITH banded AS (
  SELECT
    CASE
      WHEN discount = 0 THEN '0%'
      WHEN discount <= 0.10 THEN '0-10%'
      WHEN discount <= 0.20 THEN '10-20%'
      WHEN discount <= 0.30 THEN '20-30%'
      ELSE 'Trên 30%'
    END AS discount_band,
    sales,
    profit
  FROM fact_order_line
)
SELECT
  discount_band,
  COUNT(*) AS line_items,
  ROUND(SUM(sales), 2) AS sales,
  ROUND(SUM(profit), 2) AS profit,
  ROUND(SUM(profit) / SUM(sales) * 100, 2)
    AS profit_margin_pct
FROM banded
GROUP BY discount_band
ORDER BY MIN(
  CASE discount_band
    WHEN '0%' THEN 1 WHEN '0-10%' THEN 2
    WHEN '10-20%' THEN 3 WHEN '20-30%' THEN 4
    ELSE 5 END
);

Review checklist

Các lỗi SQL làm sai kết luận

  • Fan-out joinJoin nhiều bảng ở sai grain làm nhân sales và profit.
  • Average of averagesTrung bình margin nhóm không bằng margin tổng.
  • Incomplete periodSo YoY khi hai kỳ không có cùng số tháng.
  • Silent exclusionsINNER JOIN làm mất orphan record mà không cảnh báo.
  • Small-base rankingMargin cao trên sales rất nhỏ không đủ để ưu tiên.
  • Metric ambiguity“Order count” phải ghi rõ unique order hay line count.

1

3

Hypothesis backlog

Câu hỏi cần kiểm định tiếp

H1. High discount làm margin suy giảm?

So sánh margin trong cùng product-market-time stratum; kiểm soát mix trước khi diễn giải.

H2. Growth đang phụ thuộc một số market?

Phân rã YoY growth contribution theo market và kiểm base effect.

H3. Customer concentration tạo risk?

Đo cả sales share, profit share, purchase frequency và stability theo năm.

H4. Faster shipping tạo giá trị?

So AOV và margin theo ship mode trong cùng segment và order priority.

H5. Có seasonality đủ ổn định để forecast?

Decompose trend-seasonality, dùng rolling-origin backtest và báo MAPE/WAPE.

Scientific guardrails

Quy tắc diễn giải

Comparable denominator So sánh kỳ phải có cùng độ dài và coverage.

Materiality threshold Không xếp hạng margin khi sales base quá nhỏ.

Multiple dimensions Drill-down tuần tự để tránh cherry-picking.

Sensitivity analysis Kiểm insight dưới nhiều ngưỡng và filter.

Association language Dùng “liên quan”, không dùng “gây ra” khi chưa có causal design.

Reproducibility Insight phải trace được về query và snapshot version.
